# Released Townlight Windows installed audit

Date: November 4, 2026. Scope: the previously released Windows MSI, installed fresh in an owned Windows Sandbox. No software fixes, release replacement, Linux or macOS work, or publication was performed.

**Verdict: the released suite is not an all-pass implementation.** Substantial end-to-end workflows work, but installed testing exposed defects and incomplete deployment/UI paths. This report distinguishes those from missing fixtures, unavailable external services, correct safeguards and test-harness errors. It is not a certification that every possible input, state, button instance or deployment environment works.

## Exact tested release and method

- Release: [townlight-beta-1-windows-1.7.0.1](https://github.com/townlight/townlight/releases/tag/townlight-beta-1-windows-1.7.0.1).
- Source/tag: `706028abab771d0b4c8458e52c759a8bbd9ce3ba`.
- MSI: `Townlight-Candidate-Windows-x64.msi`, 2,082,697,216 bytes; SHA-256 `8cebaea95fa62f582326a1a0c1af3cb54233c40dbb41d88324170eb1b3f25ade`.
- MSI Authenticode: Valid, Scott Converse, Microsoft timestamp. Desktop executable SHA-256 `0ba4935b7a3ade8ee3f0ed316edc06b322169460ce6b3cd2ae6351fa73b44b99`.
- Fresh Windows Sandbox, 16 GiB RAM, networking/clipboard/GPU disabled; synthetic city, staff accounts, documents and media only. The exact published MSI was installed. The full Inspections preview composition enabled Core plus all nine selectable product modules. Station required separate explicit setup from its shipped Python payload.
- Actual installed WebView controls were driven through their DOM event handlers. Native Windows file pickers, app close/restart and Sandbox controls were exercised through native computer use. Native commands/loopback HTTP were also used for explicit fixture setup and independent persisted readback; these are identified below. CDP invocation is not proof that every control was operated with a physical mouse. The immutable native bridge could not be instrumented; empty `calls` arrays are not transport traces.
- The pinned Gemma model was staged offline and checksum verified. Real generation was exercised. Internet model downloading was not exercised.

Receipts retain original observations, including failed assertions. `CONTROL-RESULTS.csv` reconciles them with later readback. Duplicate IDs and retries are not independent workflow successes. There are currently **477 distinct observed case IDs** in the collected receipts; this is not a percentage of the total product surface.

## Explicit coverage limits

- No Linux/macOS activity and no released MSI replacement.
- Live capture/continuous on-air test scripts were rejected twice by automatic tool policy; no test processes were launched. The second rejected version used a finite feed and bounded worker and received no detailed reason. No bypass was attempted. Therefore these functions remain NOT EXERCISED.
- No physical capture card, cable headend, external YouTube/CivicCast upload, real SMTP delivery, public Internet deployment or Internet model download was tested.
- No positive Planning amendment adoption against a newly imported adopted revision; no large-dataset pagination, load/concurrency stress, full locale/accessibility matrix, power-loss recovery, second Windows version or upgrade from another installed version was tested.
- Recovery uses a disposable synthetic profile. Model cache was moved outside the profile after a complete copied snapshot to keep repeated lifecycle backups bounded. Small profile recovery does not prove model-cache restoration. Station's separate media directory is also outside the native profile snapshot.
- Synthetic citations/rules do not establish real legal compliance. Outputs were checked for retained provenance and privacy boundaries, not professional legal/accessibility/translation certification.

## Reading the delivered files

- `CONTROL-RESULTS.csv`: observed case ID, original result, reconciled result, explanation, exact receipt and method. A failed harness assertion is retained and explained rather than silently deleted.
- `RAW-OBSERVATIONS.json`: original collected case observations, including text and raw failures.
- `SOURCE-CONTROL-INVENTORY.json`: controls found in exact-release source. Conditional/legacy source is not proof of installed exposure or tested behavior.
- `INITIAL-UI-INVENTORY.json`: first installed screen inventory. Later conditional states appear in individual receipts.
- `CASE-COUNTS.json`: distinct observed IDs and raw/reconciled counts; not a coverage percentage or count of unique product functions.
- `EVIDENCE-SHA256SUMS.txt`: checksums of preserved receipts and delivered report files.

The audit did not change product source, GitHub releases, tags or the released MSI. The findings above are a report, not fixes. No all-functions release sign-off is given; explicit unexercised paths remain listed above.
