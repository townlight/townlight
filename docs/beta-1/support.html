Installation and recovery

Fresh installation. For a fresh installation, run the signed Windows 1.8.1.1 MSI, then follow first-run setup with an empty database and a new Townlight profile. Follow the first-run instructions.

Windows 1.8.1.1 has fresh-install acceptance. An in-place upgrade to 1.8.1.1 was not exercised. The previous Windows 1.8.0.1 release tested upgrade from 1.7.2.1; that result applies to 1.8.0.1. Before an existing-city evaluation, back up city data and settings, close Townlight, keep the existing %LOCALAPPDATA%\CivicSuite profile, and use the same Windows account. Keep the prior installer and a restore path. Station continues to use its separately configured service.

Follow the backup, recovery and maintenance guidance. Preserve existing data and backups. Do not rename or delete the compatibility profile directory %LOCALAPPDATA%\CivicSuite to work around a setup problem.

Verify the downloaded MSI against the release checksums and check its Authenticode signature is Valid, with signer Scott Converse. Use the exact release link here; GitHub's Latest download now resolves to this public beta. The acceptance summary describes the installed checks and their limits. Earlier local-model acceptance used a 16 GiB Sandbox; an 8 GiB run timed out without saving a draft.

For setup problems, consult troubleshooting before filing an installer issue. Do not remove a database or existing profile as a troubleshooting shortcut.

See the Windows staff workflow guide for roles and cross-module staff workflows.

If you cannot identify the owning product, start with the Suite issue tracker. For questions and evaluation feedback, use Townlight Discussions.

What to include

  • Installed version (1.8.1.1) and Windows version.
  • The selected products/profile and whether this was a fresh installation.
  • Steps to reproduce, what you expected and what happened.
  • Redacted error messages, logs or screenshots, using synthetic data where possible.

Do not attach resident information, credentials, tokens, database copies or unredacted backups to public issues. Do not post security vulnerabilities in public issues: follow the security policy and report privately to the affected repository.

Separate deployments and evidence

The resident portal requires separate deployment. The Windows installer does not provision a public website. Standalone CivicCast remains a separate product. The current Windows acceptance uses synthetic data and does not establish a live city deployment or physical broadcast acceptance. Follow each product guide for its supported workflow.
