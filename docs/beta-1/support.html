Townlight Windows beta support

Windows 1.9.2.1 signed public beta is available. It adds revisioned council packets with separate staff and public revisions, shared Meetings and Records work from a second Windows environment, and unattended portal delivery for materials staff explicitly approve. Windows 1.9.2.1 current release

The current signed public beta is Windows 1.9.2.1. Download the signed Windows x64 MSI, verify it against the published SHA-256 checksum, and read the acceptance and limits.

Acceptance used a physical Windows host and a clean Sandbox guest on that same PC, with synthetic data and a test portal. It does not establish operation on two physical PCs or a production portal. Direct MSI upgrades from earlier releases were not tested; do not treat them as verified.

Installation and recovery for Windows 1.9.1.1

Fresh installation. For a fresh installation, run the signed Windows 1.9.1.1 MSI, then follow first-run setup with an empty database and a new Townlight profile. Follow the first-run instructions.

Windows 1.9.1.1 is a signed public beta. See the acceptance summary for the verified workflows and artifact identities. Set up Station during Townlight first run.

Upgrade from an existing Windows installation. Back up your city data and settings in Townlight and close the app before running the signed MSI. Reopen Townlight under the same Windows account with your existing profile. If Station shows as unconfigured, open Settings → Modules → Townlight Station and select Set up meeting recording. After restoring a backup, start the services before checking your records. The acceptance summary identifies the 1.9.0.1 upgrade run on the earlier signed candidate. The separate verified 1.8.2.1 upgrade ended at 1.9.0.1.

Follow the backup, recovery and maintenance guidance. Preserve existing data and backups. Do not rename or delete the compatibility profile directory %LOCALAPPDATA%\CivicSuite to work around a setup problem.

Verify the downloaded MSI against the release checksums and check its Authenticode signature is Valid, with signer Scott Converse. Use the exact Windows 1.9.1.1 release link for this previous version; GitHub Latest now points to Windows 1.9.2.1. The acceptance summary describes the installed checks and their limits. Earlier local-model acceptance used a 16 GiB Sandbox; an 8 GiB run timed out without saving a draft.

For setup problems, consult troubleshooting before filing an installer issue. Do not remove a database or existing profile as a troubleshooting shortcut.

See the Windows staff workflow guide for roles and cross-module staff workflows.

If you cannot identify the owning product, start with the Suite issue tracker. For questions and evaluation feedback, use Townlight Discussions.

What to include

  • Installed version (1.9.1.1) and Windows version.
  • The selected products/profile and whether this was a fresh installation.
  • Steps to reproduce, what you expected and what happened.
  • Redacted error messages, logs or screenshots, using synthetic data where possible.

Do not attach resident information, credentials, tokens, database copies or unredacted backups to public issues. Do not post security vulnerabilities in public issues: follow the security policy and report privately to the affected repository.

Separate deployments and evidence

The resident portal requires separate deployment. The Windows installer does not provision a public website. Standalone CivicCast remains a separate product. The current Windows acceptance uses synthetic data and does not establish a live city deployment or physical broadcast acceptance. Follow each product guide for its supported workflow.
